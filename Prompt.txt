2. UPLOAD HISTORY

Implement persistent upload history.

Prefer SQLite over a large JSON history file.

Create a local database such as:

.teledrop/teledrop.db

Do not store sensitive Telegram credentials in this database.

Suggested schema:

CREATE TABLE IF NOT EXISTS uploads (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    source_url TEXT NOT NULL,
    normalized_url TEXT,
    filename TEXT,
    file_size INTEGER,
    sha256 TEXT,
    status TEXT NOT NULL,
    telegram_message_id TEXT,
    telegram_chat_id TEXT,
    error TEXT,
    retry_count INTEGER DEFAULT 0,
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL,
    completed_at TEXT
);

Use appropriate indexes:

CREATE INDEX IF NOT EXISTS idx_upload_url
ON uploads(normalized_url);

CREATE INDEX IF NOT EXISTS idx_upload_sha256
ON uploads(sha256);

CREATE INDEX IF NOT EXISTS idx_upload_status
ON uploads(status);

Possible statuses:

pending
downloading
uploading
completed
failed
skipped

Add CLI commands:

teledrop history --status failed

3. RESUME INTERRUPTED UPLOADS

This is one of the most important features.

If the user starts:

teledrop urls.txt

with:

1000 URLs

and the process crashes after item 450:

Completed: 450
Pending: 550

When the user runs:

teledrop urls.txt

again, TeleDrop must automatically detect previous progress.

It should resume from pending items.

Example:

Previous batch detected.

Total       : 1000
Completed   : 450
Failed      : 5
Pending     : 545

Resume batch? [Y/n]:

If yes:

Resuming from previous state...

Do NOT simply rely on the item index.

A URL may move within the input file.

Use a stable identity such as:

normalized URL

and preferably:

URL + file hash

when available.

A completed item must never be uploaded again.

6. DUPLICATE DETECTION

Implement duplicate detection at multiple levels.

Level 1 — URL duplicate

Normalize URLs before comparison.

For example:

https://example.com/image.jpg
https://example.com/image.jpg

must be treated as the same source.

Create a normalization function that safely handles:

- whitespace
- trailing slash where appropriate
- URL encoding
- fragments
- case normalization where appropriate

Do NOT blindly modify URL query parameters because they may be meaningful.

---

Level 2 — File hash duplicate

After downloading a file, calculate:

SHA-256

Example:

hashlib.sha256(file_bytes).hexdigest()

Before uploading:

Calculate SHA256
       ↓
Search database
       ↓
Hash already uploaded?
       ├── YES → Skip
       └── NO  → Upload

This catches cases where:

image-a.jpg
image-b.jpg

are actually identical files.

14. PERFORMANCE

The implementation must remain efficient with large files:

1,000 URLs
10,000 URLs
100,000 URLs

Do not load huge files completely into memory unnecessarily.

For SHA-256:

DO NOT read a multi-GB file into memory.

Use streaming/chunked hashing:

with open(path, "rb") as f:
    while chunk := f.read(1024 * 1024):
        sha256.update(chunk)

Use efficient database queries.
